## 1. Sprint 1 Review

### What Was Completed

- **SRS Compilation (SCRUM-20):** Finalized master Software Requirements Specification document including cover page, core functional requirements, and non-functional specifications.
- **User Stories & Acceptance Criteria (SCRUM-18):** Defined user persona flows for Donors, Hospital Staff, Camp Organizers, and System Administrators.
- **Requirements Traceability Matrix (SCRUM-19):** Mapped functional requirements directly to user stories and system modules.
- **Visual Architectural Artifacts:** Generated activity flowcharts and sequence diagrams for emergency blood request dispatching and camp slot pre-bookings.
- **Repository Governance:** Configured branch protection rules requiring formal Pull Requests (PRs) and peer approval prior to merging into `main`.

### What Was Not Completed / Scope Adjustments

- **Visual Wireframes:** Raw text stubs and temporary markdown placeholders were identified during task audits and flagged for full replacement with production UI mockups in Sprint 2.
- **Direct Commit Cleanup:** Unreviewed bulk commits pushed without pull requests required branch protection enforcement to secure repository integrity.

## 2. Sprint 1 Retrospective

### What Went Well

- Swift recovery and stabilization of repository governance through enforced branch protection rules.
- High alignment with university rubric standards for formal SRS deliverable packaging (TIEST/NED header formatting).

### What Needs Improvement

- Communication regarding file formats and deliverable standards (e.g., submitting proper visual assets rather than plain text/markdown stubs).
- Pacing of task execution to avoid rushed multi-task pushes in single windows.

### Action Plan for Sprint 2

1. **Strict PR Workflow:** Every new feature, UI wireframe, or module code must be submitted via a dedicated feature branch with detailed pull request descriptions.
2. **Quality Gate Checks:** Verify visual assets (PNG/SVG UI designs and system diagrams) before approving pull requests.
3. **Incremental Commits:** Require clean, descriptive commit messages matching SCRUM issue IDs.
